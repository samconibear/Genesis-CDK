## Overview

genesis-cdk is an npm library of AWS CDK constructs for deploying static websites on AWS — S3, CloudFront, Route53, and ACM — without needing to understand the underlying infrastructure. Consumers install the package and write a thin CDK app using the provided constructs.

## Repository Structure

```
src/                  # Library source (compiled to lib/ for publishing)
  index.ts            # Public API surface — all exports
  cert-stack.ts       # CertStack construct + SSM param name helpers
  root-site.ts        # RootSite construct (reads certArn/hostedZoneId from SSM)
  base-site.ts        # BaseSite construct (S3 + CloudFront + Route53)
  sub-site.ts         # SubSiteProps interface
  backend.ts          # Backend construct (API Gateway wired into CloudFront)
bin/                  # Example entrypoints for consumers to model from
  cert.ts             # Example: deploy CertStack (one-time per domain)
  app.ts              # Example: deploy AppStack (per-commit CI)
lib/                  # Compiled output (gitignored, generated by tsc)
```

## Consumer Experience

Consumers install `genesis-cdk`, write their own CDK app using the constructs, and deploy with `cdk deploy`:

```ts
// their lib/my-stack.ts
import * as cdk from 'aws-cdk-lib';
import { RootSite } from 'genesis-cdk';

const app = new cdk.App();
const stack = new cdk.Stack(app, 'AppStack', {
  env: { account: '123456789012', region: 'eu-west-2' },
});

const root = new RootSite({ scope: stack, domain: 'example.com', src: './dist' });
root.subSite({ domain: 'blog', src: './blog/dist' });
```

## Two-Stack Architecture

**CertStack** (always `us-east-1`, enforced internally):
- Creates Route53 Hosted Zone + ACM wildcard certificate
- Writes `certArn` and `hostedZoneId` to SSM Parameter Store at `/<domain>/certArn` and `/<domain>/hostedZoneId`
- One-time deploy per domain: `cdk deploy CertStack`

**AppStack** (consumer-specified region):
- `RootSite` reads `certArn` and `hostedZoneId` from SSM at synth time via `ssm.StringParameter.valueFromLookup()`
- No CloudFormation cross-stack dependency — SSM decouples the two stacks
- Deployed every commit: `cdk deploy AppStack`

## Construct Hierarchy

- **`CertStack`** — standalone CDK Stack, always pins to `us-east-1`
- **`RootSite`** — extends `BaseSite`; looks up SSM params and wires hostedZone + certificate
- **`BaseSite`** — core CDK Construct: S3 bucket (TLS-enforced), BucketDeployment, CloudFront distribution, Route53 A-record
- **`SubSiteProps`** — props interface passed to `baseSite.subSite()`, creates a subdomain site sharing the parent's zone and certificate
- **`Backend`** — optional: API Gateway (regional, TLS 1.2) wired into CloudFront under `/api/*`


## Key Design Notes

- `src/` is the source of truth; `lib/` is generated and not committed
- All constructs are exported from `src/index.ts` — the public API surface
- `BaseSite` uses `RemovalPolicy.DESTROY` — buckets are deleted with the stack
- SSM parameter name convention: `/<domain>/certArn` and `/<domain>/hostedZoneId` — defined in `ssmParamName` helper exported from `cert-stack.ts`
- The `Backend` construct is included but optional — not needed for pure static sites
